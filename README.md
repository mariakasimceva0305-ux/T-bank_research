# Decision-relevant memory for a lifelong agent

A controlled study of one question: **when is it better to retrieve past
experience by its effect on the agent's next decision than by how similar its
description is to the current situation?**

The setup is synthetic on purpose, so that the coupling between semantic
similarity and utility is a parameter of the generator rather than a property of
a dataset that has to be taken on trust.

## Results

Accuracy over the second half of a 400-step stream, capacity 128, `k = 4`,
5 seeds, 95% Student-t intervals. `sufficient@k` is the fraction of steps whose
retrieved set contains a memory generated by the same latent rule *and* recorded
as a success — that is, one sufficient to determine the action.

| retrieval rule | acc, rho=1 | suf, rho=1 | acc, rho=0 | suf, rho=0 |
|---|---|---|---|---|
| no memory | 0.107 ± 0.033 | 0.000 | 0.141 ± 0.012 | 0.000 |
| recency | 0.114 ± 0.023 | 0.046 | 0.139 ± 0.036 | 0.051 |
| **similarity** | **0.361 ± 0.065** | 0.774 | 0.148 ± 0.031 | **0.070** |
| similarity + success filter | 0.238 ± 0.037 | 0.830 | 0.126 ± 0.018 | 0.401 |
| similarity + MMR | 0.253 ± 0.049 | 0.514 | 0.160 ± 0.017 | 0.130 |
| influence (KL magnitude) | 0.147 ± 0.035 | 0.806 | 0.170 ± 0.026 | **0.869** |
| influence (IG) + merge | 0.146 ± 0.035 | 0.823 | 0.174 ± 0.024 | **0.861** |
| **influence (IG) + merge + floor** | 0.249 ± 0.063 | 0.777 | **0.249 ± 0.045** | 0.672 |
| oracle (same latent rule) | 0.326 ± 0.026 | 0.994 | 0.339 ± 0.051 | 0.984 |

Three findings, in order of how much they change the picture.

**Retrieval and decisions come apart.** When similarity carries no information
about the rule (`rho = 0`) it finds a sufficient memory 7% of the time, against
86% for the decision-based scores — the same rate as the oracle. That recall
does not convert: 0.861 recall buys 0.174 accuracy, because the remaining slots
fill with confident but irrelevant memories that the reader cannot arbitrate
between (measured: 1.000 accuracy with no such distractor, 0.300 with three).

**The budget is a ceiling, not a quota.** At `rho = 0` the decision-based rule
peaks at `k = 2` (0.328) and halves by `k = 6` (0.147), while similarity creeps
up with `k`. A score floor that leaves slots empty rather than filling them
gives the best non-oracle result at `k = 4` — **0.249 against similarity's
0.148**, paired difference +0.101, p = 0.013 — at *lower* recall than the
version without it, and it flattens the budget curve entirely (0.249-0.273 from
`k = 1` to `k = 6`). That is the direct test of the explanation: if the decay
came from filling slots, forbidding the fill should remove it, and it does.

A floor is available to a decision-level score and not to a description-level
one. A cosine of 0.6 means nothing on its own; a score measured in nats of
decision uncertainty removed makes "worth less than half the best candidate" a
statement one can act on.

**The advantage inverts, it does not merely vanish.** Across the coupling sweep
similarity rises monotonically (0.148 → 0.361 as `I(c;r)` goes 0 → 3 bits) while
the decision-based rules stay flat. They cross below one bit of mutual
information, and at `rho = 1` similarity beats every decision-based rule and the
oracle itself.

## Setup

Situations are generated from two independent latent factors: a **surface
cluster** `c` supplying eleven of twelve content tokens and therefore dominating
any sentence embedding, and a **latent rule** `r` appearing as a single
low-mass marker token, which alone determines the correct action.

```
project ledger_svc team fin_ops request settle journal for clearing in dc_north tag six
                   |------------------ surface cluster c ------------------|   |rule r|
```

The rule-to-action map is a bijection resampled per environment instance, so it
cannot be memorised in weights and is recoverable only from past experience.
Feedback is binary and never reveals the correct action, so a failure is
informative too — it eliminates one action.

`rho` sets `P(c = r)` and hence `I(c;r)`: 3 bits at `rho = 1`, 0 bits at
`rho = 0`. Between the regimes exactly one generator parameter changes.

The marker is deliberately a common, bland token. With rare pseudo-tokens the
encoder treats it as the most distinctive part of the sentence and cosine
similarity ranks by it, which collapses the two regimes; the measurement that
forced this choice is in `scripts/probe_embeddings.py`. After calibration the
marker is linearly decodable from the embedding at 0.979 while cosine
neighbourhoods match on the cluster 100% of the time and on the marker 28% —
the information is there, the geometry does not rank by it.

The agent is a 1.45M-parameter decoder-only transformer with a closed action
set, trained once on retrieval-agnostic contexts and then **frozen**, so a
comparison of retrieval rules is not also a comparison of agents. The closed
action set makes `pi(a | s, M)` an exact categorical distribution, so the
decision-level scores are computed rather than sampled.

## Reproduction

CPU only; no GPU was used.

```bash
pip install -r requirements.txt
pytest -q
python -m dam.train --steps 5000 --seed 0
python -m scripts.probe_embeddings
python -m scripts.probe_reader
python -m scripts.run_experiments --seeds 5 --steps 400 --capacity 128
python -m scripts.analyze
```

## Layout

```
dam/env.py        generator, coupling parameter, closed-form I(c;r), serialization
dam/model.py      decoder-only reader, exact policy over the closed action set
dam/data.py       retrieval-agnostic training contexts
dam/train.py      training of the reader (run once, then frozen)
dam/memory.py     store, eviction, and every retrieval rule under comparison
dam/evaluate.py   online evaluation protocol
scripts/          experiments, diagnostics, tables and figures
report/report.md  the study
tests/            coupling, vocabulary closure, budget parity, padding invariance
```
